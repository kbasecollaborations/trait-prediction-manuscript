\subsection*{Annotation}

\subsubsection*{Protein Sequence Analysis Using UniRef Databases}
For the analysis of protein sequences, we employed the UniRef30, UniRef50, UniRef70, and UniRef90 databases in conjunction with the UniProt-TrEMBL database. The initial step involved filtering out protein sequences that were shorter than 100 amino acids to ensure the analysis was focused on sequences of substantial length and potential functional significance. Subsequently, all qualifying protein sequences were amalgamated into a single file. This consolidation process necessitated the creation of a mapping document to link the original identifiers (ids) to the new, unified identifiers, facilitating future reference and analysis.

The merged protein sequences then underwent a similarity search against a specified database using the DIAMOND BLASTP tool. The parameters for this search were set to require a minimum query and subject coverage of 80\%, an E-value threshold of 0.001 for significance, and the use of a mid-sensitivity search mode. The output was formatted according to the standard BLAST tabular format (outfmt 6). Following the similarity search, the results were divided based on the original source files from which the protein sequences were derived. This step was crucial for maintaining the traceability of the analysis back to the original datasets.

The final stage in the protein sequence analysis involved the generation of counts dataframes. These dataframes serve as a quantitative representation of the analysis results, facilitating further statistical and comparative studies.

\subsubsection*{Genome Annotation Using EggNOG}
Genome annotation via the EggNOG database was conducted on an individual basis for each genome to optimize efficiency and reduce computational time through parallelization. The annotation process utilized the \texttt{emapper.py} script with the DIAMOND method for sequence alignment. The parameters mirrored those used in the UniRef analysis, including an E-value cutoff of 0.001 and both query and subject coverages set at 80\%, with a mid-sensitivity mode for sequence matching.

Upon completion of the annotation process, counts dataframes were generated for KEGG Orthology (KO) identifiers and seed orthologs. Notably, due to the presence of proteins with multiple KO identifiers, the resulting KO counts could exceed the total number of proteins analyzed, as each KO id was counted individually.

\subsubsection*{Kofamscan and KEGG Pathway Module Analysis}
Each genome was annotated individually using Kofamscan, a process parallelized to enhance efficiency. The \texttt{exec\_annotation} script with the \texttt{-f mapper} option was utilized for this purpose. Similar to previous steps, this stage culminated in the generation of counts dataframes, which are essential for the quantitative analysis of the annotation results.

KEGG Pathway Modules were analyzed by parsing the results obtained from Kofamscan, based on module definitions available on the KEGG website. A completion score ranging from 0 to 1 was calculated for each pathway for which there was a non-zero completion rate, providing a quantitative measure of pathway completeness. These results were then aggregated to facilitate comprehensive pathway analysis across the genomes studied.

\subsubsection*{RAST Annotation}
The RAST annotation tool provided results in JSON format, which were parsed to extract counts of ontology terms, specifically focusing on \texttt{ontology\_terms.SSO}. This parsing facilitated the generation of a counts dataframe, which is instrumental in understanding the functional landscape of the annotated genomes.

\subsubsection*{De Novo Protein Clustering}
For \textit{de novo} protein clustering, a similar approach to the initial protein sequence analysis was adopted. Protein sequences were merged into a single file, and a mapping between old and new identifiers was established. Clustering was performed using the MMSeqs2 tool, with parameters set to achieve the desired sequence identity and coverage. The \texttt{createtsv} function of MMSeqs2 was then used to generate a tab-separated values (TSV) file, which facilitated the splitting of results based on the original file sources. The concluding step involved generating a counts DataFrame, where cluster IDs were associated with new identifiers, allowing for straightforward conversion back to the original protein ids using the previously mentioned mapping document.

\subsection*{Carbon Source Utilization Datasets and Genomic Information}
This study analyzed four distinct carbon source screening datasets: ATLeaf (Schäfer et al., 2023), Literature \cite{}, Marine (Gralka et al., 2023), and PMI \cite{}. The atleaf dataset comprises growth measurements of 224 bacterial strains cultivated on 45 distinct carbon sources using minimal media on agar plates. The literature dataset encompasses 363 bacterial genomes with corresponding growth data across 65 carbon sources, compiled from published studies \cite{}. The marine dataset contains high-throughput metabolic profiling data of 186 marine heterotrophic bacteria, assessed across 135 carbon substrates in MBL media. The PMI dataset includes metabolic characterization of 55 bacterial isolates across 192 carbon sources.

Due to annotation pipeline limitations and incomplete phenotypic data, the final datasets utilized for machine learning analyses contained fewer genomes and phenotypes than the original datasets (detailed in Supplementary Table Sx). All bacterial genomes were processed through our standardized annotation pipeline to generate various feature representations for machine learning applications. To facilitate cross-dataset comparisons, we implemented a phenotype name normalization protocol to standardize carbon source nomenclature across datasets.

\subsection*{Automated Biological Feature Selection - Bio (KEGG)}
We employed a systematic approach for biological feature selection utilizing the Kyoto Encyclopedia of Genes and Genomes (KEGG) pathway database \cite{}. For each of the 16 phenotypes common across the atleaf, lit, and pmi datasets, we curated a list of relevant keywords for KEGG database queries. These queries were executed using the KEGG API to retrieve associated KO (KEGG Orthology) identifiers and orthologs from matching pathways and modules. We intentionally implemented broad keyword criteria to ensure that we comprehensively captured all the metabolically relevant KO identifiers, resulting in an extensive feature set. \subsection*{Data Pre-processing and Feature Selection}
Feature representations underwent distinct pre-processing protocols depending on the analytical objectives. All feature representations, except ``kofam\_modules'', which contained module pathway completeness scores, were converted to binary presence/absence matrices. We implemented three primary pre-processing strategies:

\begin{itemize}
    \item ``all features'' datasets: Maintained without additional pre-processing
    \item ``nocorr'' datasets: Subjected to both variance and correlation filtering. Variance filtering: Implemented using sklearn's VarianceThreshold method (threshold = 0.01). Correlation filtering: Employed a graph-based approach to eliminate highly correlated features based on network connectivity
    \item ``Bio'' datasets: Underwent biological feature selection as previously described
\end{itemize}

Furthermore, to evaluate univariate feature selection methods, we implemented ``chi2'', ``f\_classif'', and ``mutual\_info\_classif'' functions in conjunction with sklearn's SelectKBest method. Additionally, we explored dimensionality reduction through Principal Component Analysis (PCA) and Non-negative Matrix Factorization (NMF) using sklearn's decomposition module. All feature selection procedures were strictly confined to training data to prevent data leakage.

\subsection*{Null Models}
To establish performance baselines, we implemented three null model strategies:

\begin{itemize}
    \item Identity: Assigns the predicted phenotype based on the most common phenotype in the training data
    \item Bernoulli: Assigns phenotypes based on the probability of the phenotype appearing in the training data
    \item Nearest Neighbor: Assigns phenotypes based on phylogenetically closest organisms in the training data. Phylogenetic distances for the Nearest Neighbor model were calculated using the ete3 toolkit \cite{}, utilizing a comprehensive tree containing all the study organisms mapped to GTDB taxonomy.
\end{itemize}

\subsection*{Machine Learning Workflow}
Our primary machine-learning implementation utilized RandomForest \cite{} and CatBoost \cite{}. Model training incorporated evaluation set holdouts to minimize overfitting. Given the inherent class imbalance in phenotype data, we employed Matthews Correlation Coefficient and Balanced Accuracy as the primary performance metrics. Training-validation partitioning was implemented using sklearn's \texttt{train\_test\_split} method, with an 80:20 ratio, respectively.

Comparative analyses demonstrated comparable performance between CatBoost and sklearn's RandomForestClassifier. Additionally, hyperparameter optimization yielded minimal performance improvements.

\subsection*{Cross-dataset Test Performance Evaluations}
We conducted systematic cross-dataset validation to assess classifier generalizability by training models on individual source datasets (ATleaf, Literature, and Marine) and evaluating performance on independent target datasets (ATleaf, Literature, Marine and PMI). To maintain feature set consistency across train and test datasets, regardless of pre-processing or selection strategies, we implemented a feature mapping protocol. For every feature in the training data missing from the test data this involved retrieving features from the ``all features'' representation of test dataset, with any missing features imputed as zero values to ensure consistency.

\subsection*{In-clade and Out-of-clade Partitioning}
To evaluate the robustness of our predictive models across phylogenetic distances, we implemented two complementary approaches for generating phylogenetically structured test sets. The primary approach utilized the partitioning algorithm described by (Li et al. 2023), which systematically separates training and test data based on phylogenetic relationships.

We supplemented this algorithmic approach with manual class-level partitioning to provide additional validation of model performance across taxonomic boundaries. For manual partitioning, we selected major bacterial classes that were well-represented across our datasets. Specifically, we designated Gammaproteobacteria and Alphaproteobacteria as out-of-clade test cases, while Actinomycetia, Bacilli, and Bacteroidia served as in-clade test cases.

The out-of-clade analysis involved the complete removal of all members belonging to the designated test class (either Gammaproteobacteria or Alphaproteobacteria) from the training data, creating a stringent test of model generalizability across taxonomic boundaries. In contrast, we maintained class representation in the training data for in-clade analysis by removing only the specific genomes selected for testing while retaining other members of the same class in the training set.

Dataset-specific analyses were conducted to account for varying taxonomic distributions across our source datasets.

\subsection*{Recursive Feature Elimination}
We implemented Recursive Feature Elimination with Cross-Validation (RFECV) using sklearn's framework. The protocol consisted of:

\begin{itemize}
    \item Data Partitioning: Implementation of 5-fold stratified cross-validation, replicated 10 times to generate 50 distinct cross-validation splits
    \item Feature Selection: Iterative feature elimination optimizing for Matthews Correlation Coefficient
    \item Validation: Performance assessment on independent held-out validation sets
\end{itemize}

\subsection*{Combined Feature Representation}
The development of the combined feature representation integrated information from multiple annotation sources through a systematic feature selection process. Initially, we identified the top 100 features from individual feature representations based on their importance in RandomForest models, as quantified through SHAP (SHapley Additive exPlanations) analysis \cite{}. These high-importance features were then aggregated to create a comprehensive combined representation that leveraged complementary information from different annotation sources.
